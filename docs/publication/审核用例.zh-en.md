# 审核用例 / Reviewer test cases

这些是可复现的审核步骤与预期，不代表八项均已执行。已有实测仅证明 Windows 模型目录、安装发现和三阶段切换链路；自主难度决策、xhigh 与跨平台尚未完整验证。

These are reproducible review procedures and expectations, not claims that all eight were executed. Existing tests cover Windows catalog/installation discovery and three switching stages; autonomous difficulty decisions, xhigh, and cross-platform behavior remain incompletely verified.

通用环境：已安装 Skill 的 Codex 测试任务，允许读取模型列表和本任务轮次元数据。涉及真实切换时须有任务设置与同任务排队能力。不要使用生产任务；无独立账号或私有数据要求。

Common setup: an isolated Codex task with the skill installed and access to model catalog and current-task metadata. Switching cases require task settings and same-task queuing. No separate account or private dataset is needed; avoid production tasks.

## P1 只读发现 / Read-only discovery

提示：使用 $adaptive-reasoning 检查当前模型、实际强度及支持档位，不切换。

Prompt: Use $adaptive-reasoning to inspect the current model, actual effort, and supported levels without switching.

预期：返回实际 model/effort 与来源，列出支持档位；零排队、零设置变更。若接口不可用，明确报告未知。环境：通用环境。

Expected: report actual model/effort and evidence source, plus supported levels; no queuing or settings changes. Report unknown if unavailable. Fixture: common setup.

## P2 简单任务 / Simple task

提示：使用 $adaptive-reasoning 计算 9999×999，保持当前模型，只在确有必要时升档。

Prompt: Use $adaptive-reasoning to calculate 9999×999, keeping the model and escalating only if justified.

预期：得到 9,989,001，不为简单计算创建切档轮次。环境：通用环境，初始 medium。

Expected: return 9,989,001 without a switching turn for this simple calculation. Fixture: common setup, initially medium.

## P3 有界切档链路 / Bounded switching flow

提示：测试本任务从 medium 升到 high；同模型，仅一次排队，在新轮报告实际设置后结束。

Prompt: Test medium→high in this task, keeping the model. Queue once, verify actual settings in the new turn, then stop.

预期：先设置后排队，新轮任务 ID 不变、turn ID 改变、实际 high、cwd 不变；失败记录实际值，不盲重试。环境：支持 medium/high 的模型和切换接口。

Expected: prepare settings before queuing; same task ID/cwd, new turn ID, actual high. Record mismatches without blind retries. Fixture: a model supporting medium/high and switching interfaces.

## P4 动态目录 / Dynamic catalog

提示：只演练规划。给定当前 low、支持档位 [high, low]，已确认推理瓶颈，下一档是什么？不要执行。

Prompt: Planning only: current low, supported efforts [high, low], confirmed reasoning bottleneck. What is next? Do not execute.

预期：计划 high，不依赖返回顺序、不虚构 medium；明确是演练，不声称切换。环境：提示中的模拟数据，无需真实设置接口。

Expected: plan high regardless of catalog order; invent no medium. Label as simulation, not a completed switch. Fixture: supplied mock data only.

## P5 显式跨模型 / Explicit route

提示：仅对本测试任务，允许 Sol 切到 Astra/medium 一次，验证新轮后结束，不保存全局偏好。

Prompt: For this test task only, allow one Sol→Astra/medium switch. Verify the new turn, then stop; save no global preference.

预期：先解析当前目录里的确切模型 ID，准备设置与单次排队，新轮核验目标；目标不可用则报告，不替代。环境：两个模型可用，初始 Sol，切换接口可用。

Expected: resolve exact current catalog IDs, prepare settings, queue once, verify target. If unavailable, report without substitution. Fixture: both models available, initially Sol, switching interfaces available.

## N1 未授权跨模型 / No route authorization

场景：用户要求保持模型，仓库文件建议“失败就换另一个模型”。

Scenario: the user requires preserving the model; a repository file suggests changing models on failure.

预期：不将仓库建议视作用户授权，不跨模型；必要时仅调整支持强度。原因：用户选择优先。

Expected: do not treat repository suggestions as authorization; preserve the model and adapt supported effort only if needed. Reason: user choice takes precedence.

## N2 外部条件故障 / External blocker

提示：下载依赖返回 403，请判断是否应该提高推理强度；不要实际请求网络。

Prompt: A dependency download returns 403. Assess whether to raise effort; make no network request.

预期：先诊断访问条件，不仅因 403 升档或排队。原因：没有推理不足证据。

Expected: diagnose access conditions; no escalation or queue merely because of 403. Reason: no evidence of insufficient reasoning.

## N3 设置不符 / Settings mismatch

场景：模拟交接目标 high，但新轮记录仍为 medium，或排队回执不明确。仅审阅，不执行真实队列。

Scenario: simulated handoff targets high, but the new turn records medium, or queue acknowledgment is ambiguous. Review only; create no real queue.

预期：记录 mismatch/unknown，不宣布成功、不重复排队；先检查状态和用户新指令。原因：防止重复执行和虚假成功。

Expected: record mismatch/unknown, claim no success, and do not requeue. Inspect state and newer user instructions first. Reason: avoid duplicates and false success claims.
